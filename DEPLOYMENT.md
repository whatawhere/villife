# Выпуск и откат

## Порядок релиза

1. Проверить, что рабочие деревья `C:\velo` и `C:\velo-site` чистые, а изменения запушены.
2. Прогнать тесты: `deno test --no-config --allow-env --allow-net tests/`.
3. Прогнать интеграционные тесты: `VILLIFE_LIVE=1 deno test --no-config --allow-env --allow-net tests/live.test.js`.
4. Залить в staging: `deno run -A npm:wrangler@3 deploy --env staging`.
5. Проверить staging: `/warm`, `/search?q=test`, `/debug`.
6. Залить в production: `deno run -A npm:wrangler@3 deploy`.
7. Проверить production и страницу `/status/`.
8. Собрать десктопные сборки через CI, проверить установку и удаление.
9. Наблюдать за метриками первые сутки: ошибки Worker, долю успешных стартов, p95.

## Откат

- Worker: `deno run -A npm:wrangler@3 rollback --name villife-search` (или версию из `deployments list`).
- Каталог: `deno run -A npm:wrangler@3 rollback --name villife-catalog`.
- Сайт: `git revert <hash>` в `C:\velo-site` и `git push origin HEAD:main`.
- Приложение: откатить коммит в `C:\velo`, пересобрать установщик, раздать предыдущий релиз.
- D1: перед миграцией сделать выгрузку `deno run -A npm:wrangler@3 d1 export villife-catalog --remote --output backup.sql`, при откате применить её через `d1 execute --file backup.sql --remote`.
- R2: объекты не удалять при откате — старый Worker продолжит читать кэш.

## Требуются внешние ресурсы

- Подпись Windows: в секретах `SIGN_CERT` / `SIGN_PASS` лежит самоподписанный сертификат — CI подписывает сборки, но SmartScreen всё равно будет предупреждать. Для публичного релиза замени секреты на PFX от доверенного центра сертификации. Локально: `scripts/sign-windows.ps1 -Certificate <pfx> -Password <pass> -File Villife.exe`.
- Нотаризация macOS: нужны `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD` в секретах репозитория. Шаг `notarytool` уже добавлен в CI.
- Единая учётная запись: backend готов — `/auth/register`, `/auth/login`, `/auth/me` с HMAC-токенами и PBKDF2. Клиентам нужно перейти с VLF1 на эти токены.
- Персонализация рекомендаций: `/recommendations` уже учитывает частоту прослушивания исполнителей; качество улучшится по мере накопления истории.
- Коды входа по почте: нужны секреты Worker `EMAIL_API_URL`, `EMAIL_API_KEY` и переменная `EMAIL_FROM`. Формат совместим с Resend (`https://api.resend.com/emails`). Без них `/auth/email/request` возвращает 503. `EMAIL_DEBUG=1` показывает код на экране только для отладки — включать в проде нельзя.
